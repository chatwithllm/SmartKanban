## Method — Code-Driven Audit

### Step 1 — Map the web frontend
```bash
wc -l web/index.html
grep -nE "^function |^  function |^const.*=.*function|^async function" web/index.html | head -200
grep -nE "fetch\(|api\(" web/index.html | head -200
```
List every render function, event handler, and API call found.

### Step 2 — For each screen in FEATURE_PARITY_REGISTRY.md
Read the web render function completely (Rule 11 slow-read).
Then grep the macOS codebase for the equivalent:
```bash
grep -rn "<behavior keyword>" KanbanClaude.macOS/ src-macos/ src-tauri/ 2>/dev/null
```
For each web behavior with NO macOS match → log a gap.

### Step 3 — For each endpoint in the web
```bash
grep -n "fetch(\|api(" web/index.html | grep "/<endpoint>"
```
Verify endpoint exists in the macOS Endpoints.swift / API client and is called from the
correct StateManager/store. Missing endpoint or wrong path → log a gap.

### Step 4 — For each interactive behavior
grep web/index.html for: click, hover, drag, keydown, long-press, right-click, scroll.
Verify each has a macOS equivalent: Button, .gesture, .onHover, .contextMenu, etc.
Missing → log a gap.

### Step 5 (Round > 1 only) — Fix verification
For every FIX-NNN in (none — initial audit): verify the named file/line was updated and the fix
matches the spec. Log:
  Verified ✅ / Not landed ❌ / Partial ⚠ / Regression introduced 🔴
