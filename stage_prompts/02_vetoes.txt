## Classification
For each veto, label one of:
| Type | Who fixes | Action |
|------|-----------|--------|
| Read-the-code | Claude | Read source files cited, document the answer |
| Spec conflict | Claude | Pick canonical source from MACOS_APP_PLAN.md or FEATURE_PARITY_REGISTRY.md, write resolution |
| Code bug | Claude | Read code, identify wrong value, write the fix as a spec patch |
| Missing spec | Claude | Write the missing spec section |
| Process gate | Human | Document the required action; do not block |
| Count mismatch | Claude | Re-audit, correct |

## Workflow
1. Read MACOS_APP_PLAN.md completely. Extract every veto item from §7.
2. For each veto:
   a. Classify per table above.
   b. If type is Claude-resolvable: open the relevant source file(s) under `web/`, `server/`,
      or other relevant code paths and resolve. Write the resolution into VETO_RESOLUTION_PATCH.md
      as an amendment (NOT a full plan rewrite — only the deltas).
   c. If type is "Process gate": document under §"Process Gates (human action required)" with
      exact steps. Do NOT block the orchestrator.
3. After all vetoes processed: re-evaluate any confidence score that would change. If §7.5
   Buildability would now rise to >= 7, note it.
