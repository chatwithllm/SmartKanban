## Non-Negotiable Rules (from agent-rules.md — apply every task)

### Before writing ANY endpoint client code (Rule 1)
Run ALL FOUR pre-flight bash checks:
```bash
grep -nE "@.*\.route|@router\.(get|post|put|delete|patch)|app\.(get|post|put|delete|patch)" server/<file> | grep -i "<feature>"
grep -nE "Blueprint\(|APIRouter\(|express\.Router" server/<file>
grep -n "return jsonify\|return.*json\(\)\|res\.json\|res\.send" server/<file>
grep -nE "fetch\(|api\(|await fetch" web/index.html | grep -i "<feature>"
```
If any returns zero matches — STOP. Re-read; ask only if truly ambiguous after slow-read.
Never invent a path or shape.

### Before writing ANY Codable struct / response model (Rule 2)
Read the actual `return jsonify({...})` or `res.json({...})` in backend.
Mirror every key VERBATIM. snake_case in backend → CodingKeys mapping to camelCase.
If backend returns `{"items": [...], "count": N}` write a wrapper struct.
Never decode bare array.

### Swift concurrency — banned patterns (Rule 3)
  NEVER: `async let _ = foo()`          — use `withTaskGroup` instead
  NEVER: `.task { await heavyWork() }`  — use `.onAppear { Task.detached { ... } }`
  ALWAYS: catch CancellationError silently

### For every screen (Rule 5 + Rule 9 + Rule 13)
  1. `awk '/Screen: <name>/,/^---/' FEATURE_PARITY_REGISTRY.md` — get task list
  2. If any row contains "renderX", "container", "tile", "card", or "row component":
     DECOMPOSE first — read the web render function (Rule 13), list every element,
     create per-element sub-rows in the registry BEFORE writing Swift.
  3. Implement every ❌ row.
  4. Verb-check every row before marking ✅ (Rule 9):
     button → Button { } label: { }   NOT Text
     toggle/expand → @State + Button   NOT static display
     swipe → .swipeActions
     tap/navigate → NavigationLink or Button { navigate() }
  5. Run post-build validation (below).
  6. Update registry: ❌ → ✅ / 🔄 (adapted, note justification) / 🚫 (out of scope, justify).
  7. Report: ✅ <ScreenName> — N implemented, M adapted, K out-of-scope, 0 ❌ remaining

### Post-build validation — run before every done claim (Rule 6)
For SwiftUI:
```bash
xcodebuild -scheme KanbanClaude -configuration Release \
  -derivedDataPath ./DerivedData \
  -destination 'platform=macOS,arch=arm64' build 2>&1 | grep -E "error:|\*\* BUILD"
pkill -x KanbanClaude; sleep 1
rm -rf /Applications/KanbanClaude.app
cp -R ./DerivedData/Build/Products/Release/KanbanClaude.app /Applications/
xattr -dr com.apple.quarantine /Applications/KanbanClaude.app
open -a /Applications/KanbanClaude.app; sleep 6
/usr/bin/log show --last 30s --predicate 'subsystem CONTAINS "kanbanclaude"' --info --debug 2>&1 | tail -80
```

For Tauri:
```bash
cd src-tauri && cargo tauri build --target aarch64-apple-darwin 2>&1 | tail -40
# Install and tail Console.app for the bundle id "com.kanbanclaude.kanbanclaude"
```

Failure conditions (any of these = NOT done — fix first):
- `cancelled` more than once → fix concurrency (Rule 3)
- `failed:` → read full error, fix root cause
- `401|403` → fix auth header injection
- `404` → fix endpoint path (Rule 1)
- `decode|DecodingError` → fix Codable (Rule 2)
- No "loaded N <thing>" line for new screen → endpoint never returned data

`xcodebuild SUCCEEDED` / `cargo build --release` success is compile proof ONLY.

### Rule 16 — Touched files get a full rule-grep pass before commit

Remediate any live match in the SAME commit.
